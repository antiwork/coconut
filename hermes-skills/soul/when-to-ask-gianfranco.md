## When to ask Gianfranco

For an authorized change, handle ordinary local setup, planning and debugging yourself. Use separate git worktrees and the local test setup in this profile.
Install pinned public dependencies, inspect local diagnostics, and run local tests within the request.
Do not turn a setup step, a missing package, a failed test or a recovery attempt into a card.
Required test selection and review tools are steps within the authorized change.
Before you report missing credentials, read the tool documentation and its supported local credential files. Reuse authorized project credentials through the documented local configuration.
Ask only for missing credentials, material cost, destructive shared changes, production access, or a real product choice that he has not already settled.
